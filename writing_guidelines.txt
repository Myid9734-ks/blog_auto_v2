================================================================================

이 문서는 AI 에이전트가 블로그 글을 작성할 때 반드시 따라야 하는 규칙이다.
아래 규칙을 어기면 후속 스크립트(검증/업로드 단계)에서 자동으로 거부되거나
중단될 수 있다.


────────────────────────────────────────────────────────────────────────────
1단계: 작성 순서 (반드시 이 순서로 사고할 것)
────────────────────────────────────────────────────────────────────────────

1) 주제에 맞는 글을 처음부터 끝까지 완성한다 (이미지는 고려하지 않고 글에만 집중)
2) 완성된 글을 다시 검토하며, 시각적으로 보여주면 이해에 도움이 될 지점
   2~3곳을 찾는다
3) 각 지점의 바로 앞뒤 문맥에서 핵심 장면/개념을 뽑아 이미지 설명(영어, 15단어
   이내)을 작성한다
4) 최종적으로 정해진 JSON 형식에 맞춰 한 번에 출력한다

(이 사고 과정을 출력에 표시할 필요는 없다. 최종 결과물인 JSON만 출력한다)


────────────────────────────────────────────────────────────────────────────
2단계: 공통 작성 규칙 (모든 글 공통) — 두괄식 + 소제목 구조
────────────────────────────────────────────────────────────────────────────

■ 글자수
  - 전체 본문: 1,800~2,500자 (공백 포함)
  - 소제목 아래 문단 하나당 3~4줄 이내로 끊어서 작성 (긴 문단 금지)

■ 구조 (두괄식 — 검색형 블로그 글에 맞는 구조)
  전통적인 "서론-본론-결론"이 아니라, 답을 먼저 보여주고 소제목별로
  구체적으로 풀어주는 구조를 따른다.

  - 도입 (전체의 약 10%, 2~3줄)
    · 메인 키워드를 첫 문장 또는 첫 문단에 1회 포함
    · "이 글을 읽으면 무엇을 알 수 있는지" 핵심을 바로 제시 (두괄식)

  - 소제목 + 본문 블록 (전체의 약 80%, 소제목 3~4개)
    · 소제목(heading) 하나당 본문 3~4줄
    · 각 소제목 자체가 검색 의도에 대한 구체적 답이 되도록 작성
      예: "음식물쓰레기 냄새, 왜 나는 걸까?", "냉동 보관으로 냄새 차단하기"
    · 각 소제목에 연관 키워드를 자연스럽게 포함
    · 키워드 반복은 전체 글자수 대비 1~2% 이내 (과도한 반복 금지)

  - 마무리 (전체의 약 10%, 2~3줄)
    · 메인 키워드 1회 재언급
    · 핵심 내용 요약
    · (민감 등급인 경우 면책 문구 포함)

■ 금지 사항
  - 광고성 과장 표현 ("최고", "1위", "유일한") 남발 금지
  - 표절 / 타 글 짜깁기 금지 — 반드시 새로운 문장으로 재구성
  - 비교/추천형 글은 균형 있게 서술 (한쪽으로 치우친 평가 지양)


────────────────────────────────────────────────────────────────────────────
3단계: 위험도 분류 — 글을 쓰기 전, AI가 매번 스스로 판단
────────────────────────────────────────────────────────────────────────────

다음 기준으로 이번 글의 등급을 정한다.

[일반 정보] — 기본 규칙만 적용
  - 위 기준에 해당하지 않는 모든 글 (생활팁, 사용법, 비교, IT, 정리형 등)

[민감 정보] — 추가 규칙 적용
  다음 중 하나라도 해당하면 "민감"으로 분류한다:
  - 금액·수치·날짜·자격조건처럼 "틀리면 실질적 피해(금전손실, 신청실패,
    건강위험, 투자손실)"로 이어지는 정보를 다루는 글
  - 예: 정부지원금/신청, 투자/증시, 의료/건강, 법률 등


────────────────────────────────────────────────────────────────────────────
4단계: "일반" 등급 규칙
────────────────────────────────────────────────────────────────────────────

  - 확실하지 않은 내용은 "~로 알려져 있습니다" 등 완곡한 표현 사용
  - 출처 불분명한 통계 인용 금지


────────────────────────────────────────────────────────────────────────────
5단계: "민감" 등급 규칙 — 추가로 반드시 지킬 것
────────────────────────────────────────────────────────────────────────────

  1) 구체적 수치(금액, 날짜, 등락률, 자격조건 등)는 AI가 추측해서 쓰지 않는다
     → 확실한 값이 없으면 그 수치 자체를 빼고 일반론으로 서술
     → 스크립트가 별도로 실시간 데이터(예: 증시 시황)를 입력값으로 제공한
        경우, 그 값만 그대로 정리/서술하고 새로운 수치를 만들어내지 않는다

  2) 단정·선동 표현 금지
     예: "100% 받을 수 있다", "지금 사야 한다", "이건 OO병이다" (X)
     예: "~일 수 있습니다", "~인 경우가 많습니다" (O)

  3) 글 말미에 분야에 맞는 면책 문구를 1줄 반드시 삽입한다.
     예시:
     - 정책/지원금: "정확한 신청 조건과 최신 정보는 반드시 정부24, 해당
       지자체 또는 복지로 홈페이지에서 확인하시기 바랍니다."
     - 건강정보: "본 내용은 일반적인 정보 제공 목적이며, 증상이 지속되거나
       심할 경우 반드시 전문의와 상담하시기 바랍니다."
     - 투자/증시: "본 내용은 투자 참고용 정보이며, 투자 판단과 책임은
       투자자 본인에게 있습니다."
     - 그 외 민감 주제: 해당 분야의 공식 기관/홈페이지 확인을 권장하는
       문구로 자체 작성


────────────────────────────────────────────────────────────────────────────
6단계: 이미지 프롬프트 규칙
────────────────────────────────────────────────────────────────────────────

  - 모든 이미지는 아래 스타일 템플릿을 따른다 (스크립트가 자동으로 접미사를
    붙이므로, AI는 {내용 설명} 부분만 작성한다):

    "{내용 설명}, flat illustration style, minimal, soft pastel colors,
     clean composition, no text, no watermark, blog header style"

  - {내용 설명}은 해당 섹션 텍스트를 압축한 핵심 장면/개념, 영어 15단어 이내
  - 사람, 글자, 로고, 브랜드명은 절대 포함하지 않는다
  - 이미지 개수: 글 1개당 2~3개


────────────────────────────────────────────────────────────────────────────
7단계: 최종 출력 형식 (JSON)
────────────────────────────────────────────────────────────────────────────

아래 형식 외 다른 텍스트(설명, 마크다운 코드블록 ```json 등)는 절대 출력하지
않는다. 순수 JSON 텍스트만 출력한다.

{
  "title": "포스팅 제목 (30자 이내)",
  "category": "카테고리명",
  "risk_level": "general 또는 sensitive",
  "hashtags": ["태그1", "태그2", "태그3"],
  "segments": [
    {"type": "intro", "content": "도입부 내용 (2~3줄, 두괄식으로 핵심 먼저)"},
    {"type": "heading", "content": "소제목1"},
    {"type": "text", "content": "소제목1에 대한 본문..."},
    {"type": "image", "prompt": "content description here"},
    {"type": "heading", "content": "소제목2"},
    {"type": "text", "content": "소제목2에 대한 본문..."},
    {"type": "heading", "content": "소제목3"},
    {"type": "text", "content": "소제목3에 대한 본문..."},
    {"type": "image", "prompt": "content description here"},
    {"type": "outro", "content": "마무리 내용 (2~3줄, 키워드 재언급+요약)"}
  ]
}

segments의 type 종류 (5가지만 허용):
  - "intro"   : 도입부. 글 전체에서 정확히 1개, 맨 처음에 위치
  - "heading" : 소제목. 업로드 시 <h2> 스타일로 굵게 표시됨
  - "text"    : 소제목 바로 아래에 오는 일반 본문
  - "image"   : 이미지 삽입 위치. heading/text 사이에 배치
  - "outro"   : 마무리. 글 전체에서 정확히 1개, 맨 마지막에 위치

규칙:
  - heading은 3~4개, 각 heading 바로 다음에는 반드시 text가 1개 이상 와야 함
  - image는 2~3개, heading 또는 text 뒤에 자연스럽게 배치 (intro/outro 바로
    뒤에는 배치하지 않음)
  - title은 30자 이내, 기존 used_titles.json과 중복 금지
  - hashtags는 5~8개
  - risk_level이 "sensitive"인 경우, "outro" 항목의 content 끝에 해당
    분야의 면책 문구가 포함되어 있어야 한다
